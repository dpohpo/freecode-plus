你现在进入 **MERGE 模式** — 技能包打包工具。

你的任务是将用户指定的多个技能包融合为一个**新的独立技能包文件**，写入 `~/.claude/commands/`，以后用户可以直接用一个斜杠命令调用融合后的全部能力。

### 🧬 铁律传染性（核心功能）

**本技能具有铁律传染性 — 它融合产出的每一个新技能都会被自动植入全部铁律。**

传染内容（从 `~/.claude/CLAUDE.md` 读取最新版本）：
1. 反幻觉铁律头部（2 行精简版，写入新技能第 1-2 行）
2. 编码铁律+自审清单（3 行精简版，写入新技能第 4-6 行）
3. 知识沉淀+蒸馏流程（写入新技能尾部）

**传染铁律：**
- 融合前必须读取 `~/.claude/CLAUDE.md` 获取最新铁律版本，不使用缓存/记忆中的旧版
- 融合产出的文件第一行必须是反幻觉铁律，无例外
- 即使所有源技能都没有铁律头部，融合产出仍然必须包含（传染是无条件的）
- 缺少任何一层铁律的产出 = 不合格，必须修复后才能写入

## 输入格式

```
/merge 技能1 技能2 [技能3 ...] [> 新技能名]
```

- 技能名之间用空格分隔
- 排列顺序 = 优先级顺序（左高右低），用于冲突解决时高优先级覆盖低优先级
- `> 新技能名` 可选，指定输出文件名。如不指定，自动拼接所有技能名（如 `mece` + `hypothesis` → `mecehypo`；`fix` + `mode` + `hard` → `fixmodehard`）

### 示例

```
/merge mece hypothesis              → 生成 ~/.claude/commands/mecehypo.md
/merge mece hypothesis > scout      → 生成 ~/.claude/commands/scout.md
/merge fixmode hardest truthseek    → 生成 ~/.claude/commands/fixhardtruth.md
```

## 执行流程

### 步骤一：加载源文件

1. 解析 `$ARGUMENTS`，提取所有技能名和可选的输出名
2. 对每个技能名，**读取** `~/.claude/commands/<技能名>.md` 的完整内容
3. 文件不存在 → 列出 `~/.claude/commands/` 下所有可用技能，让用户重新选择
4. 全部加载成功后，进入融合流程

> **铁律：必须读取源文件原文，不凭记忆，不凭猜测。**

### 步骤二：原子化解构（MECE）

对每个源技能执行拆解：

1. 提取**原子指令**（不可再分的最小指令单元）
2. 每条标注**六维分类**：
   - `[身份]` 你是谁 — 角色、能力声明
   - `[思维]` 怎么想 — 推理框架、分析方法
   - `[行为]` 怎么做 — 操作步骤、工作流
   - `[验证]` 怎么确认 — 验证方法、终止条件
   - `[输出]` 怎么呈现 — 格式、结构
   - `[约束]` 不能做什么 — 限制、边界
3. 每条标注**来源**：`[源:<技能名>]`

### 步骤三：冲突检测

对所有**跨源的同维度**原子指令对扫描四类冲突：

| 类型 | 特征 |
|------|------|
| **直接矛盾** | 逻辑上不可同时为真 |
| **资源竞争** | 争夺同一执行槽位（如两种输出格式） |
| **优先级模糊** | 都适用但未定义谁先 |
| **隐性冲突** | 表面兼容，执行时矛盾 |

### 步骤四：冲突解决

对每个冲突，按优先级依次尝试 5 种策略，**首个可行的即采纳**：

1. **时序分层** — 分配到不同阶段，在时间上消解
2. **条件分支** — 设互斥触发条件，在条件上消解
3. **层级嵌套** — 一条作外层框架，另一条作内层细节
4. **能力叠加** — 本质不冲突，直接合并增强
5. **优先级覆盖** — 按用户输入顺序，左边覆盖右边

每个解决方案须通过**双轨验证**：
- **逻辑验证**：指令集是否自洽？
- **场景验证**：模拟执行是否产生矛盾？

### 步骤五：合成新技能文本

将融合后的原子指令重新组装为一篇**流畅、自然、可直接作为 prompt 使用**的技能文档：

**合成原则：**
- 身份叠加：多个角色能力直接合并
- 思维串联：按 `广度 → 深度 → 验证` 自然序编排
- 行为编排：生成清晰的分阶段工作流
- 验证增强：所有验证手段叠加保留
- 约束从严：取最严格的约束
- 输出兼容：覆盖所有源技能的输出要求

**文本要求：**
- 写成完整、独立的技能 prompt，不引用或依赖源技能文件
- 风格与现有技能包保持一致（参考源技能的语言风格）
- 末尾包含 `$ARGUMENTS` 占位符，使新技能可接收用户输入
- 不包含任何关于融合过程本身的说明（用户看到的是成品，不是制造过程）

### 步骤六：自洽性终检

对合成的文本做最终检查：
1. 通读全文，确认每条指令与所有其他指令零冲突
2. 构造极端场景测试是否自洽
3. 确认从输入到输出是完整闭环
4. 有问题 → 回步骤四修复，最多 3 轮

### 步骤七：写入文件

1. 将最终文本写入 `~/.claude/commands/<新技能名>.md`
2. 如果目标文件已存在 → **先告知用户，询问是否覆盖**
3. 写入成功后输出：

```
✅ 已生成新技能包：/<新技能名>
📦 融合了：/<技能1> + /<技能2> [+ /<技能3> ...]
📄 文件：~/.claude/commands/<新技能名>.md
⚡ 冲突处理：检测到 N 个冲突，全部已解决
   - [简要列出每个冲突及采用的策略]

现在可以直接使用 /<新技能名> 了。
```

## 最终步：知识沉淀 + 蒸馏

融合完成后，判断是否值得存入知识库：

**存入条件**（满足任一）：融合过程中发现重要的技能设计模式 | 冲突解决方案有复用价值 | 用户要求

**执行流程：**
1. 主动问用户：「要存入知识库吗？」
2. 若是 → 生成完整版写入 `~/.claude/knowledge/YYYY-MM-DD-<关键词>.md`
3. 立即执行五层蒸馏（L1清除装饰→L2电报体→L3结构压缩→L4语义去重→L5可推导裁剪）
4. 蒸馏版写入 `~/.claude/knowledge/YYYY-MM-DD-<关键词>.distilled.md`（目标 ≤ 原文25%）
5. 输出：`📄 完整版：XXX 字符 ⚗️ 蒸馏版：YYY 字符（压缩率 ZZ%）`

**双版本铁律：完整版用于人类阅读和回溯，蒸馏版用于 AI 快速检索加载。两版必须同时生成，缺一不可。**
