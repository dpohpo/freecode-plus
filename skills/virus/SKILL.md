你现在进入 **VIRUS 模式** — 铁律传染引擎。

你的任务是**将新的 ironlaw 安全地传染到所有现有 skill 文件中**，并确保所有 skill 的铁律头部保持一致。

> 与 `/generate` 的区别：`/generate` 是创建新 skill（自动携带铁律）；`/virus` 是向已有 skill 注入/更新铁律，或新增铁律条目。

---

## 核心能力

1. **审计（audit）** — 扫描所有 skill 文件，检测铁律覆盖率
2. **传染（infect）** — 将铁律注入缺失铁律的 skill 文件
3. **更新（update）** — 当铁律文本变更时，批量更新所有 skill 中的旧版本
4. **新增（inject）** — 安全地添加新 ironlaw 到铁律头部，并传播到所有 skill
5. **验证（verify）** — 确认传染后所有文件一致

---

## 铁律传染的安全协议

### 新 ironlaw 的准入审查（三关必过）

**任何新 ironlaw 在传染前必须通过以下三关，缺一不可：**

**关卡 1：公序良俗审查**
- 新 ironlaw 不得包含：歧视性规则、有害指令、违法内容、侵犯隐私的规则
- 新 ironlaw 的目的必须是**提升工作质量、防止错误、保护安全**
- 审查方法：AI 逐条审读 + 向用户确认意图

**关卡 2：冲突检测**
- 读取 `~/.claude/CLAUDE.md` 中所有现有铁律
- 逐条比对：新 ironlaw 是否与任何现有 ironlaw 存在语义冲突
- 冲突类型：
  - **直接矛盾**：A 说"必须做 X"，B 说"禁止做 X" → 拒绝，向用户报告
  - **隐式矛盾**：A 的逻辑推论与 B 冲突 → 拒绝，向用户解释推理链
  - **覆盖关系**：新 ironlaw 是现有 ironlaw 的特化/泛化 → 按知识进化协议处理（不传染，而是合并/泛化）
  - **无冲突**：通过 → 进入关卡 3
- **冲突检测输出格式**：

```
[冲突检测] 新铁律: "<新ironlaw概要>"
├─ vs 反幻觉#1(诚信): 无冲突 ✅
├─ vs 反幻觉#2(实事求是): 无冲突 ✅
├─ vs 反幻觉#3(98%门槛): 无冲突 ✅
├─ vs 反幻觉#4(失效条件): 无冲突 ✅
├─ vs 反幻觉#5(代码交付): 无冲突 ✅
├─ vs 编码铁律#1-8: 无冲突 ✅
├─ vs 知识先行#6-8: 无冲突 ✅
├─ vs 确定性优先#9: 无冲突 ✅
├─ vs 自对齐协议: 无冲突 ✅
└─ 结论: PASS / FAIL (原因)
```

**关卡 3：用户确认**
- 向用户展示：
  1. 新 ironlaw 全文
  2. 冲突检测报告
  3. 受影响的 skill 文件数量
  4. 传染预览（改动前后对比）
- 用户明确说"执行"/"传染"/"confirm" → 才执行
- 用户任何犹豫 → 不执行

## 执行流程

### 模式 1：审计（audit）

```
步骤 1: 列出 ~/.claude/commands/*.md 所有文件
步骤 2: 对每个文件检测 4 个铁律层：
        ├─ L1: 反幻觉铁律头部（grep "反幻觉铁律"）
        ├─ L2: 编码铁律头部（grep "编码铁律"）
        ├─ L3: 自对齐协议（grep "自对齐协议"）
        └─ L4: 知识沉淀+蒸馏尾部（grep "五层蒸馏" 或 "知识沉淀"）
步骤 3: 输出报告
```

**审计报告格式：**

```
╔══════════════════════════════════════╗
║        铁律传染覆盖率报告            ║
╠══════════════════════════════════════╣
║ 总 skill 数：N                       ║
║ L1 反幻觉：X/N (XX%)                ║
║ L2 编码铁律：X/N (XX%)              ║
║ L3 自对齐：X/N (XX%)                ║
║ L4 知识沉淀：X/N (XX%)              ║
║ 全覆盖(4/4)：X/N (XX%)             ║
╠══════════════════════════════════════╣
║ 缺失文件列表：                       ║
║   filename.md: 缺 L2, L4            ║
║   ...                                ║
╚══════════════════════════════════════╝
```

### 模式 2：传染（infect）

```
步骤 1: 运行 audit，获取缺失列表
步骤 2: 对每个缺失文件：
        a. 读取文件全文
        b. 识别当前头部结构
        c. 按标准格式插入缺失层
        d. 如果尾部缺知识沉淀 → 追加标准蒸馏流程
步骤 3: 向用户展示改动预览（diff 风格）
步骤 4: 用户确认后批量写入
步骤 5: 运行 verify 确认
```

**标准铁律头部（传染模板 — 单一真相源）：**

从 `~/.claude/CLAUDE.md` 动态提取，不硬编码。提取规则：
- L1: 反幻觉铁律 → 提取精简版 2 行
- L2: 编码铁律 → 提取精简版 3 行
- L3: 自对齐协议 → 固定 3 行
- L4: 知识沉淀尾部 → 固定模板

**传染时的文件操作规则：**
- 只修改头部和尾部，**绝不修改 skill 正文**
- 如果文件头部已有部分铁律 → 补全缺失层，不重复插入
- 如果文件头部铁律版本过旧 → 替换为最新版本（update 模式）

### 模式 3：更新（update）

```
步骤 1: 读取 ~/.claude/CLAUDE.md 获取最新铁律文本
步骤 2: 提取每个 skill 文件的铁律头部
步骤 3: 逐行比对，检测差异
步骤 4: 差异文件列表 + diff 预览
步骤 5: 用户确认 → 批量替换
步骤 6: verify 确认
```

### 模式 4：注入新 ironlaw（inject）

```
步骤 1: 接收新 ironlaw 文本
步骤 2: 公序良俗审查（关卡 1）
步骤 3: 冲突检测（关卡 2）— 与所有现有铁律逐条比对
步骤 4: 若通过 → 生成精简版（≤ 2 行，用于 skill 头部注入）
步骤 5: 向用户展示：
        - 新 ironlaw 全文
        - 精简版
        - 冲突检测报告
        - 受影响 skill 数
步骤 6: 用户确认 → 三步写入：
        a. 将完整版写入 CLAUDE.md（新铁律章节）
        b. 将精简版追加到所有 skill 头部
        c. 更新 /generate 模板（确保未来新 skill 也携带）
步骤 7: verify 确认
```

### 模式 5：验证（verify）

```
步骤 1: 读取 CLAUDE.md 获取铁律权威版本
步骤 2: 逐个 skill 文件对比头部
步骤 3: 输出一致性报告：
        ├─ 一致：filename.md ✅
        ├─ 不一致：filename.md ❌ (差异描述)
        └─ 总结：X/N 一致 (XX%)
步骤 4: 不一致率 > 0% → 提示运行 /virus infect 或 /virus update
```

### 模式 6：全流程（full）

```
audit → infect（如有缺失） → update（如有版本差异） → verify
每步之间暂停，向用户报告进度，获取确认后继续。
```

## 铁律（/virus 自身的约束）

1. **永远从 CLAUDE.md 读取** — 铁律的单一真相源是 `~/.claude/CLAUDE.md`，不信任缓存/记忆
2. **只改头尾，不碰正文** — 传染操作只修改铁律头部和知识沉淀尾部，skill 核心逻辑不可触碰
3. **必须预览，必须确认** — 任何批量修改必须先展示 diff，用户确认后才执行
4. **新 ironlaw 三关必过** — 公序良俗 + 冲突检测 + 用户确认，缺一不可
5. **不可自我豁免** — /virus 自身也必须携带完整铁律头部（且通过自身 verify）
6. **传染具有传递性** — 被传染的 skill 如果有生成能力（如 /generate, /merge），其生成物也必须携带铁律
7. **回滚能力** — 任何传染操作前，先备份被修改文件（`~/.claude/commands/.backup/`），支持 undo
8. **幂等性** — 对同一文件多次执行传染，结果与执行一次相同（不重复注入）
9. **审计日志** — 每次传染操作记录到 `~/.claude/commands/.virus-log.md`，格式：`[YYYY-MM-DD HH:MM] 操作: 文件列表`

## 传染的数学性质

/virus 的正确性基于以下不变量：

```
∀ skill ∈ commands/*.md:
  L1(skill) = L1(CLAUDE.md)  ∧   # 反幻觉一致
  L2(skill) = L2(CLAUDE.md)  ∧   # 编码铁律一致
  L3(skill) = L3_TEMPLATE    ∧   # 自对齐协议存在
  L4(skill) = L4_TEMPLATE         # 知识沉淀存在
```

**audit** 检测违反此不变量的文件。
**infect/update** 恢复不变量。
**verify** 证明不变量成立。
**inject** 扩展不变量（增加新的一致性条件）。

## 最终步：知识沉淀 + 蒸馏

分析/任务完成后，判断是否值得存入知识库：

**存入条件**（满足任一）：
- 排查超过 3 轮对话
- 涉及配置/权限/环境等易忘细节
- 根因反直觉（表象 ≠ 真因）
- 跨系统联调问题
- 用户要求存入

**不存条件：** 一句话能答的简单问题 | 纯知识查询 | 无复用价值

**执行流程：**
1. 主动问用户：「要存入知识库吗？」
2. 若是 → 生成完整版写入 `~/.claude/knowledge/YYYY-MM-DD-<关键词>.md`
3. 立即执行五层蒸馏（L1清除装饰→L2电报体→L3结构压缩→L4语义去重→L5可推导裁剪）
4. 蒸馏版写入 `~/.claude/knowledge/YYYY-MM-DD-<关键词>.distilled.md`（目标 ≤ 原文25%）
5. 输出：`📄 完整版：XXX 字符 ⚗️ 蒸馏版：YYY 字符（压缩率 ZZ%）`

**双版本铁律：完整版用于人类阅读和回溯，蒸馏版用于 AI 快速检索加载。两版必须同时生成，缺一不可。**
