你现在进入 **MD 模式** — 问题解决知识库构建与检索系统。

核心理念：**解决过的问题不再重复解决。** 每次分析和解决一个重要问题后，将思路和结论沉淀为 `.md` 文件，形成你的专属知识库。下次遇到问题，优先从知识库中检索已有方案。

## 两种工作模式

### 模式 A：存入（分析完问题后调用）

当你刚分析/解决完一个问题，调用 `/md` 存入知识库：

```
/md save [主题关键词]
```

**执行步骤：**

1. **回顾当前对话**，提取刚才解决的问题的核心内容
2. **生成结构化 `.md` 文件**，格式如下：

```markdown
# [问题标题 — 一句话概括]

> 创建时间：YYYY-MM-DD
> 标签：#标签1 #标签2 #标签3
> 置信度：高/中/低
> 状态：已解决 / 部分解决 / 待验证

## 问题描述
[出了什么问题？什么场景下出现的？]

## 根因分析
[问题的核心本质是什么？为什么会出现？]

## 解决方案
[怎么解决的？具体步骤是什么？]

## 关键命令/代码
[如果有关键命令或代码片段，列在这里，方便直接复制使用]

## 踩坑记录
[排查过程中走过的弯路、排除的错误假设、容易混淆的点]

## 举一反三
[这个问题的解决思路可以推广到哪些类似场景？]
```

3. **文件命名**：`YYYY-MM-DD-<关键词>.md`（如 `2026-02-07-twilio-china-blocked.md`）
4. **确保目录存在**：如果 `~/.claude/knowledge/` 不存在，先创建
5. **写入完整版后，立即执行五层蒸馏**（L1清除装饰→L2电报体→L3结构压缩→L4语义去重→L5可推导裁剪）
6. **蒸馏版写入** `YYYY-MM-DD-<关键词>.distilled.md`（目标 ≤ 原文25%）
7. **输出双版本确认**：
```
📄 完整版：~/.claude/knowledge/YYYY-MM-DD-<关键词>.md（XXX 字符）
⚗️ 蒸馏版：~/.claude/knowledge/YYYY-MM-DD-<关键词>.distilled.md（YYY 字符，压缩率 ZZ%）
```

**⚠️ 双版本铁律：完整版供人类阅读回溯，蒸馏版供 AI 快速检索加载。两版必须同时生成，缺一不可。**

### 模式 B：检索（遇到新问题时调用）

当遇到新问题，调用 `/md` 先搜索知识库：

```
/md [问题描述]
```

**执行步骤：**

1. **扫描知识库**：读取 `~/.claude/knowledge/` 下所有 `.md` 和 `.distilled.md` 文件的标题和标签
2. **语义匹配**：将用户的问题与已有知识条目进行匹配，找出相关条目
3. **加载策略（双版本检索协议）**：
   - **AI 自用加载** → 读 `.distilled.md` 蒸馏版（省 token，信息密度高）
   - **展示给用户 / 需要完整上下文** → 读 `.md` 完整版
   - **⚠️ 绝对不要搞混**：`.distilled.md` 是压缩版给 AI 用，`.md` 是完整版给人看
4. **分流决策**：
   - **找到高度相关的** → 加载知识（按上述策略选版本），基于已有方案快速解决
   - **找到部分相关的** → 展示相关条目作为参考，同时进行新的分析
   - **没找到相关的** → 告知"知识库中无此问题的记录"，然后正常分析问题
5. **分析完成后自动提议**：问题解决后，主动问用户"要存入知识库吗？"

## 判断规则

### 什么值得存入？

- 排查花了超过 3 轮对话的问题
- 涉及配置、环境、权限等容易忘记的细节
- 有坑的安装/部署流程
- 反直觉的根因（表面现象和真实原因不一致）
- 跨系统联调问题（如 ngrok + Twilio + ElevenLabs）
- 任何用户明确要求存入的内容

### 什么不需要存？

- 一句话就能回答的简单问题
- 纯粹的知识查询（不涉及排查过程）
- 用户没有要求、且不具有复用价值的内容

## 知识库管理命令

```
/md save [关键词]     → 将当前问题存入知识库
/md [问题描述]        → 检索知识库 + 分析问题
/md list              → 列出知识库所有条目（标题 + 日期 + 标签）
/md update [文件名]   → 更新已有条目（补充新发现）
/md delete [文件名]   → 删除过时条目
```
