## 核心定义

**SCHOOL = Skill & tool CHOOsing Layer**

skill 和 tool 的谐音 → school。来「学校」找现成的技能和工具，不要闭门造车。

**为什么是 constraint：**
- 不研究就编码 = 垃圾上优化（用户原话）
- 不查工具就干活 = 重复造轮子 + 浪费 token
- 知识先行铁律要求：先搜索后推理再构建
- 已有 37+ 技能包 + 未来持续增长的工具库 → 不查就用不上

## Token 节约策略

| 场景 | 节约方法 |
|------|---------|
| 简单任务用了重型技能 | SCHOOL 会降级推荐（如 L1 任务不推 /mecebest） |
| 多技能可选时 | 推荐最轻量且足够的那个 |
| 用户已在技能包内 | 不重复加载（避免技能套娃） |
| 后处理可选时 | 仅在有复用价值时推荐 /md |
| announcement.md 有专用工具 | 优先推荐专用工具（比通用技能更省） |

## 铁律

1. **[HARD] 不可跳过** — SCHOOL 是 constraint，收到任务后必须先匹配再执行
2. **[HARD] 最小足够** — 推荐能完成任务的最轻量技能组合，不过度装备
3. **[HARD] 用户指定优先** — 用户已指定 `/技能名` 时，SCHOOL 仅补充建议，不覆盖
4. **[SOFT] 读 announcement.md** — 如果 `~/Desktop/announcement.md` 存在，必须先读取再匹配
5. **[SOFT] 组合不超过 3 个** — 推荐的技能组合最多 3 个，超过则合并或降级
6. **[PREF] 速度感** — SCHOOL 匹配应在 5 秒内完成，不做深度分析（那是技能本身的事）

## 最终步：知识沉淀 + 蒸馏

分析/任务完成后，判断是否值得存入知识库：

**存入条件**（满足任一）：
- 发现新的技能匹配模式
- 匹配失败后找到更优路径（值得记录）
- 用户要求存入

**不存条件：** 常规匹配成功 | 无复用价值

**执行流程：**
1. 主动问用户：「要存入知识库吗？」
2. 若是 → 生成完整版写入 `~/.claude/knowledge/YYYY-MM-DD-<关键词>.md`
3. 立即执行五层蒸馏（L1清除装饰→L2电报体→L3结构压缩→L4语义去重→L5可推导裁剪）
4. 蒸馏版写入 `~/.claude/knowledge/YYYY-MM-DD-<关键词>.distilled.md`（目标 ≤ 原文25%）
5. 输出：`📄 完整版：XXX 字符 ⚗️ 蒸馏版：YYY 字符（压缩率 ZZ%）`

**双版本铁律：完整版用于人类阅读和回溯，蒸馏版用于 AI 快速检索加载。两版必须同时生成，缺一不可。**
