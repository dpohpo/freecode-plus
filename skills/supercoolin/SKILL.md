## 核心架构：8-Phase 认知管线（内向增强版）

```
P0a LOCAL-DEEP → P0b WEB-MINIMAL(1轮) → P1 DECOMPOSE → P2 WEIGHT
→ P3 DEEP-ANALYZE(增强) → P4 HYPOTHESIZE(增强) → P5 INTERNAL-VERIFY → P6 SYNTHESIZE
```

每个 phase 的输出是下一个 phase 的输入。管线不可跳步，不可倒序。
P3↔P4↔P5 可以内部循环（分析→假设→验证→发现新问题→再分析）。

**与 /supercooler 的核心差异**：
- P0a：从「扫描」升级为「深挖」— 不止关键词匹配，还做本地知识的交叉推理

- P3：从「六维度认知」升级为「六维度 + 内部推理链深化」— 增加推理链长度和交叉密度
- P5：从「网络多轮验证」改为「内部一致性验证优先」— 用逻辑自洽性和内部交叉验证替代网络搜索

**WHY**: 本地知识库是经过验证的高置信度资产。SUPERCOOLIN 不仅读取它们，还要在本地知识之间做交叉推理，挖掘隐含联系。

**执行**：

**第一层：全量扫描（同 supercooler）**

```

通道 L3: 记忆文件扫描 — Grep "<topic关键词>" ~/.claude/projects/*/memory/
通道 L4: MEMORY.md 索引 — 读取 MEMORY.md 的知识库索引区，查找相关条目
通道 L5: 知识文件元数据 — 对匹配文件检查状态（active/specialized/invalidated）
```

**第二层：本地知识交叉推理（SUPERCOOLIN 专属）**

```
通道 L6: 跨文件关联推理 — 不同知识文件之间是否存在未被显式标注的逻辑关联？
  → 文件 A 的结论 + 文件 B 的前提 → 能推出什么新结论？
  → 文件 C 的约束参数 + 文件 D 的边界条件 → 交集是什么？

  → 如果知道 X 在条件 α 下成立，但不知道条件 β → 这是真正的缺口

通道 L8: 知识置信度交叉校验 — 用一个知识文件的结论验证另一个的前提
  → 两个独立路径得出相同结论 → 内部置信度提升
  → 两个文件结论矛盾 → 🚨 内部冲突，高价值发现
```

## P5: INTERNAL-VERIFY — 内部优先验证

**WHY**: SUPERCOOLIN 的验证以内部一致性为主，网络验证为辅。内部验证不等于不验证 — 它用更严格的逻辑自洽标准替代更广泛的来源覆盖。

对每个假设执行内部优先的验证流程：

```
🔬 P5 验证矩阵（内部优先）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

假设 H1：「……」

第一轮（内部逻辑一致性验证）：
  → 假设与 P3 六维度分析的一致性：是/否（哪些维度支持，哪些反对）
  → 假设的推导链是否有逻辑跳跃：是/否
  → 假设是否与本地知识库的 VERIFIED 结论矛盾：是/否
  → 内部一致性评分：XX%

第二轮（反向推理验证）：
  → 假设为真 → 能预测什么？→ 预测与已知事实是否一致？
  → 假设为假 → 应该观察到什么？→ 是否观察到？
  → 反向验证评分：XX%

第三轮（替代解释排除）：
  → 同样的证据是否有其他解释？
  → 为什么 H1 优于替代解释？（奥卡姆剃刀 + 解释力）
  → 替代排除评分：XX%

第四轮（仅对外部事实性声明 — 单轮网络校准）：
  → 如果假设涉及外部事实（版本、API、配额等）→ 单次 WebSearch 校准
  → 如果假设纯基于内部推理 → 跳过本轮
  → 网络校准结果：一致/矛盾/无法验证

裁决：
  INTERNALLY_VERIFIED (≥90%) — 六维度一致 + 反向验证通过 + 替代排除
  INFERRED (75-89%)         — 内部推理支持但未经外部验证
  HIGH_CONFIDENCE (60-74%)  — 内部推理支持但有可识别的脆弱环节
  DISPUTED                  — 内部推理矛盾或外部校准矛盾
  SPECULATIVE (<60%)        — 推理链过长或假设过多

置信度：XX%
置信度来源标注：纯逻辑 X% | 模式匹配 Y% | 本地知识 Z% | 外部验证 W%
```

**SUPERCOOLIN 验证铁律**：
- 内部验证通过 3 轮才能标 INTERNALLY_VERIFIED
- 纯逻辑推导占比 ≥ 50% 的结论 → 内部验证可信度更高
- 模式匹配占比 ≥ 50% 的结论 → 必须降一级，除非有本地知识交叉验证
- 涉及外部事实的声明 → 即使内部推理完美，也必须走第四轮网络校准
- 诚实标注：INFERRED ≠ VERIFIED，让用户清楚知道置信度来源

**P3↔P4↔P5 循环**：验证结果可能推翻假设 → 回到 P3 补充分析 → 新假设 → 再验证。循环直到所有高权重概念的关键假设达到 INTERNALLY_VERIFIED 或 DISPUTED。

## 铁律（SUPERCOOLIN 专属）

1. **[HARD] 内部优先** — 80% 认知资源投入内部推理，20% 投入外部搜索。不允许反转。
2. **[HARD] 本地深挖** — P0a 不仅扫描，还要做本地知识交叉推理（L6/L7/L8）。
3. **[HARD] 网络限 1 轮** — P0b 最多 3 次搜索工具调用，只补最关键的 1 个缺口。严禁扩展。
4. **[HARD] 推理链审计** — 每条推理链必须标注：纯逻辑步 vs 模式匹配步，以及最脆弱环节。
5. **[HARD] 诚实标注来源** — INTERNALLY_VERIFIED ≠ VERIFIED。必须让用户清楚置信度来自内部推理还是外部验证。
6. **[HARD] 先拆再深** — 必须先 MECE 拆解（P1）再加权深挖（P2-P3）。未拆解就分析 = 盲人摸象。
7. **[HARD] 权重即资源** — 不平均分配认知资源。权重 5 追到基岩，权重 1 一句话。
8. **[HARD] 六维度全开 + 增强** — 权重 ≥ 4 的概念，六个认知维度缺一不可，且每维度都有 SUPERCOOLIN 专属的内部增强检查。
9. **[HARD] 可证伪才是假设** — P4 的每个假设必须有明确的证伪条件。不可证伪 = 删除。
10. **[HARD] 内部验证三轮** — P5 的内部验证（逻辑一致性 + 反向推理 + 替代排除）三轮缺一不可。
11. **[HARD] 外部事实必须外部校准** — 涉及版本/API/配额等外部事实的声明，即使内部推理完美，也必须做一次网络校准。
12. **[HARD] 双层表达** — 每个核心结论必须同时有专家级和通俗级两种表达。
13. **[HARD] 思维链全程可见** — 零黑箱。每一步推理都显示，包括被放弃的路径。
14. **[HARD] 冲突是宝藏** — 维度间冲突、内部矛盾、推理链裂缝 → 深挖，这里藏着最深的洞察。
15. **[HARD] 管线不可跳步** — P0a→P0b→P1→P2→P3→P4→P5→P6，不可跳步不可倒序（P3-P5 内部循环除外）。
16. **[SOFT] 防瘫痪** — P0a ≤ 10% | P0b ≤ 3% | P0总计 ≤ 13% | 省下的资源全部投入 P3-P4。
17. **[SOFT] 动态调权** — 分析过程中发现权重有误立即修正。

分析完成后，判断是否值得存入知识库：

**存入条件**（满足任一）：分析超过 3 轮 | 有反直觉发现 | 有复用价值 | 用户要求

**执行流程：**
1. 主动问用户：「要存入知识库吗？」
2. 若是 → 生成完整版写入 `~/.claude/knowledge/YYYY-MM-DD-<关键词>.md`
3. 立即执行五层蒸馏（L1清除装饰→L2电报体→L3结构压缩→L4语义去重→L5可推导裁剪）
4. 蒸馏版写入 `~/.claude/knowledge/YYYY-MM-DD-<关键词>.distilled.md`（目标 ≤ 原文25%）
5. 输出：`📄 完整版：XXX 字符 ⚗️ 蒸馏版：YYY 字符（压缩率 ZZ%）`

**双版本规则：完整版用于人类阅读和回溯，蒸馏版用于 AI 快速检索加载。两版必须同时生成，缺一不可。**
