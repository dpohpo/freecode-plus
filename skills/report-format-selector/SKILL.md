## 工作流程

### Phase 1: 报告需求分析（BHT）

使用 `/bht` 模式对用户输入进行分析：
- 识别报告类型需求
- 识别内容复杂度
- 识别时间敏感度
- 识别格式要求

### Phase 2: 格式族MECE分析（MECEBEST）

对提供的格式族进行MECE拆解：

**维度A: 格式族分类**
- Markdown纯格式族
- Markdown增强格式族
- 系统级格式族
- 图格式族
- 数据格式族

**维度B: 人类可读性**
- 纯文本 vs 工具支持
- 语法高亮
- 结构化程度

**维度C: Git友好度**
- 版本控制能力
- diff可读性
- 冲突处理

**维度D: 双链可靠性**
- 链接实现方式
- 断链风险
- 双向链接能力

**维度E: 可扩展性**
- 插件生态
- API开放程度
- 自定义能力

**维度F: 语义强度**
- 元数据支持
- 查询语言
- 结构化程度

**维度G: 工具生态**
- 成熟度
- 多样性
- 社区活跃度

**维度H: 迁移性**
- 数据导入导出
- 格式转换
- 供应商锁定

**维度I: 最佳角色**
- 知识库角色
- 课程系统角色
- 笔记工具角色
- 出版系统角色

**维度J: 主要代价/坑**
- 学习曲线
- 配置复杂度
- 维护成本
- 已知限制

**维度K: 推荐场景**
- 个人笔记
- 团队协作
- 课程开发
- 系统集成
- API开发

### Phase 3: 结论生成（MECEBEST）

基于MECE分析结果，生成加权结论：
- 按综合评分排序
- 输出Top 5推荐
- 提供选择理由

### Phase 4: 报告生成（REPORT-GEN）

使用 `/report-gen` 技能生成最终报告：
- 综合所有分析结果
- 生成结构化报告
- 保存到指定目录

## 格式知识库

### Markdown纯格式族

**代表格式**: `.md` 纯文本文件

**优势**:
- 极简门槛，任何文本编辑器可打开
- Git原生支持，版本控制友好
- 可读性强，适合人类直接阅读和编辑
- 轻量级，无额外依赖

**劣势**:
- 缺少结构化，需要外部工具支持
- 链接实现依赖手动输入或插件
- 语义查询能力弱
- 元数据支持有限

**综合评分**: 82分

---

### Markdown增强格式族

**代表格式**:
- Markdown + WikiLink `[[link]]`
- Markdown + Frontmatter (YAML/TOML)

**优势**:
- 保留Markdown的所有优势
- 双链支持（WikiLink原生双向链接）
- 元数据支持（Frontmatter）
- 工具生态成熟（Obsidian/Logseq等）

**劣势**:
- 链接语法非标准，兼容性问题
- 不同工具实现方式不一致
- 依赖特定生态

**综合评分**: 88分

---

### 系统级格式族

**代表格式**:
- Org-mode, Obsidian Vault, Logseq Graph

**优势**:
- 强大的结构化能力（标题、折叠、属性）
- 双链可靠性高（Org ID系统）
- 丰富的插件生态
- 任务管理集成

**劣势**:
- 学习曲线陡峭
- Emacs生态依赖（Org-mode）
- 非开发者友好的语法

**综合评分**: 85分

---

### 图格式族

**代表格式**:
- Mermaid, DOT (Graphviz)

**优势**:
- 可视化表达清晰
- 适合流程图、架构图
- 工具支持好

**劣势**:
- 不适合作为知识主存储
- 编辑器支持有限
- 大规模图性能问题

**综合评分**: 75分

---

### 数据格式族

**代表格式**:
- JSON-LD, RDF/Turtle, CSV Edge List

**优势**:
- 标准化程度高
- API友好，机器处理容易
- 语义推理能力强

**劣势**:
- 人类可读性差
- 需要专门工具编辑
- Schema治理复杂

**综合评分**: 70分

## 推荐算法

### 评分计算

```
综合分 = Σ(维度分 × 权重)

维度权重分配：
  A: 格式族分类 — 15%
  B: 人类可读性 — 20%
  C: Git友好度 — 10%
  D: 双链可靠性 — 10%
  E: 可扩展性 — 10%
  F: 语义强度 — 10%
  G: 工具生态 — 10%
  H: 迁移性 — 5%
  I: 最佳角色 — 5%
  J: 主要代价/坑 — 10%
  K: 推荐场景 — 5%
```

### 场景适配矩阵

| 用户场景 | 推荐格式 | 理由 |
|---------|---------|------|
| **快速笔记/个人知识库** | Markdown纯 | 轻量、通用、无门槛 |
| **结构化个人知识库** | Markdown增强 | Obsidian/Logseq生态成熟 |
| **团队协作知识库** | Org-mode/org-roam | 双链可靠、任务集成 |
| **课程开发** | Org-mode | 大纲强、教学一体化 |
| **系统/API集成** | JSON-LD/RDF | 标准化、机器可读 |
| **知识图谱** | Mermaid/DOT | 可视化、推理支持 |
| **学术研究笔记** | Markdown纯 | Git友好、可发表 |
| **专业出版** | LaTeX | 排版质量、期刊标准 |

## 执行流程

1. **接收用户输入**
2. **调用 /bht 分析需求**
3. **执行MECE拆解分析**
4. **生成格式推荐报告**
5. **调用 /report-gen 生成最终报告**
6. **保存到 ~/Desktop/报告/ 目录/**

---

## 使用说明

当用户调用此技能时：
1. 首先询问报告的具体需求和用途
2. 分析用户对格式族的偏好或限制
3. 基于场景匹配推荐Top 5格式
4. 为每个推荐提供详细理由
5. 生成格式对比表辅助用户决策
