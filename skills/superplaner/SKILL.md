## 核心架构：6-Phase 谋定后动管线

```
P0 GIANT-SEARCH → P1 GAP-ASSESS → P2 PLAN → P3 EXECUTE → P4 REFLECT → P5 CLOSE
                                              ↕
                                         ERROR-LOOP
                                        (P4 ↔ P3)
                                      max 10 iterations
                                     ↓ (if > 10)
                                   P5-BAIL: 存档撤退
```

**管线核心逻辑**：
- P0-P2 是「谋定」— 搜巨人 → 评估缺口 → 制定计划
- P3-P4 是「后动」— 执行 → 遇错反省 → 修正执行
- P5 是「收尾」— 成功则沉淀，失败则存档
- **P3↔P4 的循环有硬性上限：同一问题 ≤ 10 次**

**防瘫痪**：P0 ≤ 20% 总时间 | GitHub 搜索 ≤ 5 轮 | 补充搜索 ≤ 3 轮 | 连续 2 轮无增量 → 停止。

## P4: REFLECT — 遇错反省：/supercoolin 驱动的根因分析

**WHY**: 遇到错误就重试 = 赌博。停下来用 /supercoolin 分析根因，理解了再行动，是工程师和赌徒的区别。

**触发条件**：P3 中出现 🟠 REFLECT / 🔴 HALT / 💀 CRASH

**执行协议**：

```

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

错误/问题描述：
  ……（完整错误信息、上下文、已尝试的方法）

🔍 启动 /supercoolin 根因分析：

  📚 P0a 本地知识深挖：
    → 知识库中有类似问题的记录吗？
    → 历史 session 遇到过吗？

  🧠 六维度快速诊断（聚焦错误本身）：
    ① 逻辑：错误的因果链是什么？
    ② 直觉：第一直觉觉得问题在哪？
    ③ 类比：类似的错误模式见过吗？
    ④ 元认知：我是否在犯认知偏差？（确认偏差/锚定效应）
    ⑤ 系统：错误是局部的还是系统性的？
    ⑥ 第一性原理：回到最基础，什么是确定的？

  🎯 根因诊断：
    表面原因：……
    深层原因：……
    根因：……
    置信度：XX%

  💊 修复方案：
    方案 A：……（置信度 XX%）
    方案 B：……（置信度 XX%）

  ⚖️ 决策：
    □ FIX — 根因明确（≥ 95%），修复后返回 P3 重试
    □ PIVOT — 根因在当前路径上无解，切换到 P2 的回退方案
    □ ESCALATE — 问题超出预期，需要回到 P0 重新搜索巨人方案
    □ BAIL — 已用完 loop 预算，进入 P5-BAIL 存档撤退

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**P4 决策流程图**：

```
P4 REFLECT
  │
  ├── 根因置信度 ≥ 95%？
  │     ├── YES → FIX → 返回 P3 执行修复
  │     └── NO → 能切换路径吗？
  │              ├── YES → PIVOT → 切换到回退方案，返回 P3
  │              └── NO → 需要更多信息？
  │                       ├── YES → ESCALATE → 返回 P0 重新搜索
  │                       └── NO → loop 是否用完？
  │                                ├── YES → BAIL → P5-BAIL
  │                                └── NO → 再试一次 → 返回 P3
```

**反省质量要求**：
- 不允许「试试看」— 每次重试必须有根因分析支撑
- 不允许重复同一修复方案 — 如果方案 A 失败了，不能再试方案 A
- 每次反省必须产出新认知（为什么上一次失败？学到了什么？）

## 铁律（SUPERPLANER 专属）

### 谋定铁律（P0-P2）

1. **[HARD] 巨人优先** — 必须先搜 GitHub，三轮确认无方案才允许自建。「我觉得没有」不算确认，必须搜了才算。
2. **[HARD] 缺口量化** — P1 必须产出量化的覆盖度矩阵，不允许模糊的「差不多能用」。
3. **[HARD] 计划先行** — P2 的计划必须包含：动作 + 前置条件 + 验证方法 + 回退方案。缺任何一项 = 计划不合格。
4. **[HARD] Loop 预算制** — 计划阶段就必须分配 loop 预算（总计 ≤ 10）。不允许无限制重试。
5. **[HARD] 用户确认** — P2 计划完成后必须等待用户确认才进入 P3。不允许自动开始执行。

### 后动铁律（P3-P4）

6. **[HARD] 95% 门控** — 每步完成后必须验证置信度。< 95% 不得进入下一步。这是安全阀，不是建议。
7. **[HARD] 遇错即停** — 运行报错时，禁止无脑重试。必须先进入 P4 反省，理解根因后才能重试。
8. **[HARD] /supercoolin 驱动反省** — P4 的根因分析必须使用 /supercoolin 的六维度快速诊断。不允许猜测式修复。
9. **[HARD] 不重复失败方案** — 如果方案 A 在 P4 中被判定失败，禁止在后续 loop 中重试方案 A（除非有新信息改变了前提条件）。
10. **[HARD] 10 次熔断** — 同一任务累计 10 次 loop 仍未解决 → 强制进入 P5-BAIL。不允许突破上限。这是硬熔断，不是软建议。

### 收尾铁律（P5）

11. **[HARD] BAIL 必须完整存档** — P5-BAIL 的报告必须包含全部 10 次 loop 的完整轨迹、所有尝试过的方案、所有反省结论。不允许省略。
12. **[HARD] 成功也沉淀** — P5-SUCCESS 的经验必须评估是否值得存入知识库。遇到 ≥ 3 次 loop 的任务必须存。
13. **[HARD] BAIL 后不续命** — P5-BAIL 触发后，当前 session 不允许以任何形式继续该任务。必须在新 session 中重启（届时会自动读取 BAIL 报告）。

### 全局铁律

14. **[HARD] 管线不可跳步** — P0→P1→P2→P3→P4→P5，不可跳步。P3↔P4 循环除外。
15. **[HARD] 思维链全程可见** — 零黑箱。每一步推理都显示，尤其是错误反省环节。
16. **[SOFT] 防瘫痪** — P0 ≤ 20% 总时间 | P2 ≤ 15% 总时间 | 余下全给 P3-P4 执行。
17. **[SOFT] 动态调整** — 执行过程中发现计划有误 → 更新计划，但不重置 loop 计数。

## 最终步：知识沉淀 + 蒸馏

**无论 SUCCESS 还是 BAIL**，都会触发知识沉淀评估：

**存入条件**（满足任一）：loop ≥ 3 | 有新发现 | 有复用价值 | BAIL 触发 | 用户要求

**执行流程：**
1. 生成完整版写入 `~/.claude/knowledge/YYYY-MM-DD-superplaner-<关键词>.md`
2. 执行五层蒸馏（L1清除装饰→L2电报体→L3结构压缩→L4语义去重→L5可推导裁剪）
3. 蒸馏版写入 `~/.claude/knowledge/YYYY-MM-DD-superplaner-<关键词>.distilled.md`（≤ 原文25%）
4. 输出：`📄 完整版：XXX 字符 ⚗️ 蒸馏版：YYY 字符（压缩率 ZZ%）`
