# OpenCode Collaboration

This skill turns Codex-to-OpenCode coordination into a 6.0b workflow: the assistant must send a concrete message to the interactive OpenCode chat window using the bundled bash scripts, not call `opencode run` and not merely describe what OpenCode should be told.

The session policy is deterministic: reuse the existing OpenCode tmux chat if present; otherwise open `~/Desktop/OpenCode.app`, which creates/shows the same OpenCode tmux chat; then inject the prompt.

`~/Desktop/OpenCode.app` is generated by `scripts/install-desktop-app.sh`; it reads `$HOME/.local/state/opencode-skill/launch.env` so send scripts can pass the intended cwd/session/window through macOS `open`.

## Required Behavior

When this skill triggers:

1. Identify the sender as `Codex` and recipient as `OpenCode`.
2. Compile a self-contained prompt with:
   - task objective
   - relevant file paths
   - conclusions or evidence gathered so far
   - exact questions or requested decisions for OpenCode
   - expected output format
3. Send the prompt with `scripts/opencode-send-compiled.sh` or its alias `scripts/opencode-send.sh`.
4. Report whether the injection succeeded and identify the tmux target pane/window.
5. Start replies from Codex with `/codex`. Tags are sender identity signatures: OpenCode signs messages with `$opencode`; Codex signs replies with `/codex`.

## Bash Interface

Compiled delivery, equivalent to `$cct` for OpenCode:

```bash
/Users/poincare/.codex/skills/opencode/scripts/opencode-send.sh "message"
```

Or pipe longer content:

```bash
cat prompt.md | /Users/poincare/.codex/skills/opencode/scripts/opencode-send.sh --title "Jarvis review"
```

Useful options:

- `--title TEXT` sets a task title in the envelope.
- `--cwd PATH` sets the working directory if the OpenCode TUI must be bootstrapped.
- `--focus` switches tmux to the OpenCode pane after sending and opens Terminal if the session is detached. This is the default.
- `--no-focus` sends without pulling the chat window forward.
- `--no-desktop` skips `~/Desktop/OpenCode.app` and bootstraps directly in tmux.
- `--raw` sends exact text without the Codex/OpenCode wrapper.

Raw injection into the OpenCode chat pane:

```bash
/Users/poincare/.codex/skills/opencode/scripts/opencode-main-send.sh "literal text"
```

OpenCode -> GLM/freeglm loop handoff:

```bash
bash /Volumes/金阳/brain/scripts/opencode-to-glm.sh --run-id ID --cwd PATH "executor task"
```

Full 6.0b loop start and verification:

```bash
bash /Volumes/金阳/brain/scripts/triad-6b.sh loop --cwd PATH "task"
bash /Volumes/金阳/brain/scripts/triad-6b.sh verify --cwd PATH
```

Show the OpenCode chat window:

```bash
/Users/poincare/.codex/skills/opencode/scripts/opencode-attach.sh
```

Regenerate the desktop app:

```bash
/Users/poincare/.codex/skills/opencode/scripts/install-desktop-app.sh
```

## Constraints

- Do not use GUI automation or clipboard injection for this skill.
- Do not call `opencode run`; this skill targets the chat window/TUI.
- Do not use `eval`.
- Keep the prompt self-contained; OpenCode should not need prior chat history.
- Prefer absolute paths for files OpenCode should inspect.
- If no OpenCode tmux pane exists, the script opens the desktop OpenCode app, which attaches or bootstraps `tmux new-session -s opencode-main ... opencode`.
