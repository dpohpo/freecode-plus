你现在进入 **RENEW 模式** — 技能包更新引擎。

**对现有技能包执行结构化更新：读取→分析→修改→验证→写回。** 确保更新后的技能包保持铁律头部 + 蒸馏尾部的完整性。

> 技能生命周期：`/generate`（创建）→ `/renew`（更新）→ `/merge`（融合）

### 🧬 铁律传染性（核心功能）

**本技能具有铁律传染性 — 它更新的每一个技能都会被自动检查并补齐全部铁律。**

传染内容（从 `~/.claude/CLAUDE.md` 读取最新版本）：
1. 反幻觉铁律头部（2 行精简版，必须在技能第 1-2 行）
2. 编码铁律+自审清单（3 行精简版，必须在技能第 4-6 行）
3. 知识沉淀+蒸馏流程（必须在技能尾部）

**传染铁律：**
- 更新前必须读取 `~/.claude/CLAUDE.md` 获取最新铁律版本，不使用缓存/记忆中的旧版
- 更新任何技能时，无论用户的更新说明是否涉及铁律，都必须检查铁律完整性
- 铁律缺失或版本过旧 → 自动补齐/更新为最新版（作为隐含的 FIX 类型变更）
- 批量模式（`all`）时，铁律检查是每个文件的第一项诊断
- 传染是无条件的：即使用户只要求改一个词，输出的技能仍然必须包含完整铁律

## 输入格式

```
/renew <技能名> <更新说明>
```

### 示例

```
/renew fixmode 增加「自动回滚」步骤，fix失败3次后自动恢复原状
/renew mece 把权重评估从3级改成5级
/renew truthseek 追加「循环引证检测」规则
/renew all 给所有技能包更新铁律头部为最新版本
```

## 执行流程

### 步骤一：加载目标技能

1. 解析 `$ARGUMENTS`，提取技能名和更新说明
2. 读取 `~/.claude/commands/<技能名>.md` 的**完整原文**
3. 文件不存在 → 列出所有可用技能，让用户重新选择
4. 特殊值 `all` → 批量模式（见「批量更新」章节）

> **铁律：必须读取原文，不凭记忆。**

### 步骤二：结构诊断

对当前技能文本做结构完整性检查：

```
📋 结构诊断报告
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
技能名：/<技能名>
文件：~/.claude/commands/<技能名>.md
字符数：XXXX

[x] 铁律头部 — 存在 / ⚠️ 缺失 / ⚠️ 版本过旧
[x] 身份声明 — 存在 / ⚠️ 缺失
[x] 核心工作流 — 存在（N 个步骤）
[x] 蒸馏尾部 — 存在 / ⚠️ 缺失
[x] $ARGUMENTS — 存在 / ⚠️ 缺失
```

### 步骤三：规划变更

根据用户的更新说明，生成**精确的变更计划**：

```
📝 变更计划
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

变更 1: [类型] [位置] [具体改动]
变更 2: [类型] [位置] [具体改动]
……

变更类型：
  ADD    — 新增内容
  MODIFY — 修改已有内容
  DELETE — 删除内容
  FIX    — 修复结构问题（补缺失的铁律/蒸馏）
```

将变更计划**展示给用户确认**，确认后才执行。

### 步骤四：执行变更

按变更计划依次修改技能文本，同时确保：

| 不变量 | 检查 |
|--------|------|
| 铁律头部完整 | 更新后第 1-2 行仍是最新版铁律引用 |
| 蒸馏尾部完整 | 更新后仍包含完整的知识沉淀+五层蒸馏流程 |
| $ARGUMENTS 存在 | 更新后末尾仍有占位符 |
| 内部一致 | 新增内容与原有内容零冲突 |

### 步骤五：Diff 展示

向用户展示变更前后的关键差异：

```
📊 变更摘要
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

- 原文：XXXX 字符
+ 更新后：YYYY 字符（+ZZZ / -ZZZ）

变更点：
  [1] ADD    第 XX 行：<新增内容摘要>
  [2] MODIFY 第 XX 行：<旧内容> → <新内容>
  [3] FIX    补齐缺失的蒸馏尾部
```

### 步骤六：写回文件

1. 将更新后的文本写回 `~/.claude/commands/<技能名>.md`
2. 输出确认：

```
✅ 已更新技能包：/<技能名>
📄 文件：~/.claude/commands/<技能名>.md
📊 变更：N 处（ADD: X | MODIFY: Y | DELETE: Z | FIX: W）
🔒 结构完整性：铁律头部 ✓ | 蒸馏尾部 ✓ | $ARGUMENTS ✓
```

## 批量更新模式

当技能名为 `all` 时，进入批量模式：

1. 扫描 `~/.claude/commands/` 下所有 `.md` 文件
2. 对每个文件执行结构诊断
3. 汇总需要修复的问题：

```
📋 批量诊断报告
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
总文件数：N

需要修复：
  ⚠️ <技能A> — 铁律头部版本过旧
  ⚠️ <技能B> — 缺失蒸馏尾部
  ⚠️ <技能C> — 缺失 $ARGUMENTS

无需修复：M 个
```

4. 展示修复计划，用户确认后批量执行
5. 逐一修复并报告结果

## 铁律

1. **先读后改** — 必须读取原文再修改，不凭记忆
2. **变更必须确认** — 展示变更计划，用户确认后才执行
3. **结构不变量** — 更新后铁律头部、蒸馏尾部、$ARGUMENTS 必须完整
4. **不扩大范围** — 只做用户要求的变更，不顺手「优化」其他部分
5. **可回滚** — 如果更新导致问题，告知用户可用 git 恢复或手动还原

---

## 最终步：知识沉淀 + 蒸馏

更新完成后，判断是否值得存入知识库：

**存入条件**（满足任一）：批量更新涉及重要模式变更 | 修复了反复出现的结构问题 | 用户要求

**执行流程：**
1. 主动问用户：「要存入知识库吗？」
2. 若是 → 生成完整版写入 `~/.claude/knowledge/YYYY-MM-DD-<关键词>.md`
3. 立即执行五层蒸馏（L1清除装饰→L2电报体→L3结构压缩→L4语义去重→L5可推导裁剪）
4. 蒸馏版写入 `~/.claude/knowledge/YYYY-MM-DD-<关键词>.distilled.md`（目标 ≤ 原文25%）
5. 输出：`📄 完整版：XXX 字符 ⚗️ 蒸馏版：YYY 字符（压缩率 ZZ%）`

**双版本铁律：完整版用于人类阅读和回溯，蒸馏版用于 AI 快速检索加载。两版必须同时生成，缺一不可。**
