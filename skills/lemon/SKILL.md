# 🍋 Lemon — Amazon 市场分析 Agent Team

> **版本**: v1.0 | **作者**: Poincare | **创建日期**: 2026-02-27

---

## 技能描述

启动 Amazon 市场可行性分析 Agent Team。由指挥官 **Lemon** 协调四个专业下属执行完整的类目/niche 分析流程。

### 团队架构

```
┌─────────────────────────────────────────────────┐
│                    LEMON (指挥官)                 │
│     制定计划 → 分配任务 → 整合结论 → 输出决策      │
└──────────┬──────────┬──────────┬────────────────┘
           │          │          │          │
     ┌─────▼────┐ ┌──▼──────┐ ┌▼────────┐ ┌▼──────────┐
     │RESEARCHER│ │ANALYST  │ │SKEPTIC  │ │POLICY     │
     │数据采集  │ │市场分析 │ │审计验证 │ │GUARD      │
     │标注来源  │ │建模计算 │ │CoVe流程 │ │合规成本   │
     └──────────┘ └─────────┘ └─────────┘ └───────────┘
```

### 团队成员职责

| Agent | 文件 | 核心职责 |
|-------|------|----------|
| **Lemon** | `~/.claude/agents/lemon.md` | 总指挥：制定分析计划、协调团队、整合结论、输出决策备忘录 |
| **Researcher** | `~/.claude/agents/researcher.md` | 数据采集：搜索/清洗/标注来源，只做取数不做判断 |
| **Analyst** | `~/.claude/agents/analyst.md` | 市场分析：六维度评估、利润建模、差异化挖掘 |
| **Skeptic** | `~/.claude/agents/skeptic-auditor.md` | 审计验证：CoVe验证、反证搜索、打回修订 |
| **PolicyGuard** | `~/.claude/agents/policy-guard.md` | 合规审查：数据获取合规、API成本控制、类目合规风险 |

## 使用方式

### 方式 1: 带参数直接分析
```
/lemon <类目/产品关键词> [站点] [模式]
```

**示例**：
- `/lemon yoga mat` - 分析 US 站点 yoga mat 类目
- `/lemon 智能手表 JP` - 分析日本站点智能手表类目
- `/lemon wireless earbuds UK quick` - 英国站点快速筛查

**支持的站点**：US(默认), UK, DE, JP, CN
**支持的模式**：quick(快速筛查15-20min), deep(深度分析60-90min, 默认)

### 方式 2: 交互式输入
```
/lemon
```
然后按提示输入分析目标。

## 输出内容

分析完成后将输出：

1. **会话中显示**：完整的决策备忘录
2. **文件保存**：`~/Desktop/amazon-reports/[类目名]_分析备忘录_[日期].md`

### 决策备忘录包含

- 📊 **综合判断**：Go/Dig Deeper/Watch/No-Go + 置信度
- 🎯 **六维度评估**：市场容量、竞争烈度、利润空间、进入壁垒、差异化空间、趋势走向
- 💰 **利润模型**：Bear/Base/Bull 三场景 + 敏感性分析
- ⚠️ **风险矩阵**：8类风险量化评估
- 🔍 **差异化机会**：痛点分析、功能Gap、价格带空白
- 📋 **下一步建议**：最小验证实验方案

## 分析流程

```
Phase 0: 任务澄清
   └─ 确认分析范围、用户资源禀赋、分析深度

Phase 1: 数据采集 (Researcher)
   └─ POE数据、竞品数据、趋势数据、成本数据、合规数据

Phase 2: 分析处理 (Analyst)
   └─ 六维度评估、竞争结构画像、利润模型、差异化挖掘、风险矩阵

Phase 3: 审计验证 (Skeptic)
   └─ CoVe验证、交叉验证、乐观偏差检查、逻辑谬误检查

Phase 4: 合规审查 (PolicyGuard)
   └─ 数据获取合规、API成本、类目合规风险评估

Phase 5: 输出备忘录 (Lemon整合)
   └─ 综合判断、数据局限性声明、下一步建议
```

## 铁律（团队核心原则）

1. **绝不编造数据** - 没有就说没有，不用"大约"掩盖
2. **绝不伪造来源** - 每个数据点必须标注来源和时间窗
3. **推测与事实分离** - 用不同句式区分事实/推断/建议
4. **不利信息等权重** - 风险和机会用同等篇幅呈现
5. **不确定性显式化** - 每个核心结论必须附带置信度评级
6. **合规优先** - 禁止用爬虫直接抓取 Amazon
7. **冲突证据必呈现** - 发现矛盾数据必须说明
8. **Fail Closed** - 数据不足时默认保守，不给乐观结论

## 数据证据分级

| 等级 | 说明 | 示例 |
|------|------|------|
| **L1 (一级)** | Amazon 官方数据 | POE, Brand Analytics, BSR, SP-API |
| **L2 (二级)** | 授权第三方工具 | Helium 10, Jungle Scout, Keepa, Google Trends |
| **L3 (三级)** | 仅供参考 | 博客、论坛、YouTube、黑盒算法评分 |

## 置信度评级

```
★★★★★ 高置信   — 多源交叉验证，数据充分，逻辑自洽
★★★★☆ 较高置信 — 主要数据点已验证，少量推断成分
★★★☆☆ 中等置信 — 部分数据来自单一来源或推算值
★★☆☆☆ 低置信   — 数据不足，存在较多推断
★☆☆☆☆ 猜测     — 缺乏数据支撑，仅供启发
```
