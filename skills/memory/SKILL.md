## 核心定义

**/memory ≠ /md**

| 维度 | /md（语义记忆） | /memory（情景记忆） |
|------|----------------|-------------------|
| 存什么 | 教训、结论、方案 | 经历、过程、完整上下文 |
| 类比 | 教科书 | 日记 |
| 认知科学 | 皮层固化（what） | 海马体重放（when + what + why + who） |
| 何时用 | 分析完问题后沉淀教训 | 对话中途/结束时保存全部经历 |
| 文件位置 | `~/.claude/knowledge/` | `~/Desktop/memory.md` + `~/Desktop/memorydistillation.md` |
| 检索场景 | 遇到相似问题时查方案 | 新 session 加载「昨天发生了什么」 |

**一句话：/md 记「学到了什么」，/memory 记「发生了什么」。**

---

## 文件定义

| 文件 | 路径 | 作用 | 模式 |
|------|------|------|------|
| **memory.md** | `~/Desktop/memory.md` | 全保真情景记忆（完整段落） | 追加（APPEND） |
| **memorydistillation.md** | `~/Desktop/memorydistillation.md` | 压缩版情景记忆（速查） | 追加（APPEND） |

两个文件都是**追加模式**——每次调用 `/memory` 在文件末尾添加一个新段落（segment），不覆盖历史内容。随时间增长，形成完整的外脑时间线。

## 执行流程

### 第一步：确定捕获边界

```
捕获范围 = [上一次 /memory 调用位置] → [当前位置]

如果是本 session 第一次调用：
  捕获范围 = [session 开始] → [当前位置]
```

回溯对话，找到上一次出现 `/memory` 指令的位置，该位置之后到现在的所有内容即为本次捕获范围。

### 第二步：提取情景记忆（9 维度全覆盖）

从捕获范围内，提取以下 9 个维度的信息。**不是选择性摘要，是全量提取——宁多勿漏**：

```
📌 维度 1：用户的原始请求与意图
   — 用户说了什么？真正想要什么？（区分表面请求和深层意图）

📌 维度 2：做出的决策及理由
   — 选了方案 A 不选 B，为什么？
   — 用户拍板的 vs AI 建议的

📌 维度 3：发现的事实
   — VERIFIED 的事实（附来源）
   — SUSPICIOUS / UNVERIFIED 的事实（标注状态）
   — 被证伪的假设

📌 维度 4：踩过的坑与解决方案
   — 遇到了什么错误/阻塞？
   — 怎么解决的？（或还没解决）

📌 维度 5：创建/修改的文件清单
   — 文件路径 + 一句话说明变更内容
   — 新建 vs 修改 vs 删除

📌 维度 6：代码变更摘要
   — 关键函数/类/模块的变更
   — 不贴全部代码，只记结构性变更

📌 维度 7：未完成事项与下一步
   — 还没做完的事（TODO）
   — 下一步应该做什么
   — 阻塞项

📌 维度 8：团队状态（如有 agent team）
   — 哪些 agent 在工作？状态如何？
   — 任务分配情况

📌 维度 9：用户态度与偏好信号
   — 用户表达了什么偏好/不满/赞同？
   — 「用户原话」标注（这些是最重要的记忆锚点）
```

### 第 2.5 步：记忆冲突检测与裁决

**[HARD] 写入前必须执行此步。** 新提取的 9 维度信息与已有记忆可能存在冲突——同一事实的不同版本、决策的反转、TODO 的状态变化。不裁决就写入 = 记忆污染。

#### 2.5.1 加载已有记忆

读取 `~/Desktop/memorydistillation.md`（如果存在）。用蒸馏版加载，省 token。

#### 2.5.2 逐维度冲突扫描

对 9 个维度的每一个，将新提取内容与已有记忆交叉比对：

```
🔍 冲突扫描矩阵
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

对每个维度：
  新信息 ↔ 已有记忆 → 三种结果：

  🟢 一致（CONSISTENT）
     — 新旧信息不矛盾，直接追加

  🟡 演化（EVOLVED）
     — 旧信息没有错，但已过时/被更新
     — 例：TODO 从「未完成」变为「已完成」
     — 处理：新 segment 中标注演化关系：
       「⟳ 更新 S#[旧编号]：[旧状态] → [新状态]」

  🔴 冲突（CONFLICT）
     — 新旧信息直接矛盾，不可能同时为真
     — 例：S#3 说「用 Electron」，现在说「改用 Tauri」
     — 处理：启动深度裁决（见 2.5.3）
```

#### 2.5.3 冲突深度裁决（🔴 触发时）

发现 🔴 冲突时，对每个冲突点执行以下裁决流程：

```
🔴 冲突裁决协议
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

┌─ 第一层：事实核验 ─────────────────────┐
│                                         │
│ 旧记忆声明：[X]                          │
│ 新信息声明：[Y]                          │
│ X 和 Y 不可能同时为真                     │
│                                         │
│ X 的证据链：[来源、验证方式、置信度]       │
│ Y 的证据链：[来源、验证方式、置信度]       │
│                                         │
│ → 证据更强的一方胜出                      │
│ → 如果都无强证据 → 进入第二层              │
└─────────────────────────────────────────┘

┌─ 第二层：纵深追问（/deepest 思维）──────┐
│                                         │
│ 为什么会冲突？                           │
│   ⬇️                                    │
│ 是环境变了？还是之前就错了？              │
│   ⬇️                                    │
│ 如果环境变了 → 🟡 演化（旧的在旧环境下对）│
│ 如果之前就错了 → 🔴 纠正（旧的需标注失效）│
│   ⬇️                                    │
│ 纠正的根因是什么？                       │
│   🪨 追到基岩                            │
└─────────────────────────────────────────┘

┌─ 第三层：六维度交叉验证（/best 思维）───┐
│                                         │
│ 逻辑 ↔ 直觉：冲突双方哪个逻辑更自洽？    │
│ 类比：类似场景中，哪个结论更常见？        │
│ 第一性原理：从零推导，会得到哪个结论？    │
│ 元认知：我是否因锚定效应偏向旧记忆？      │
│ 系统思维：这个冲突在更大系统中意味着什么？ │
│                                         │
│ → 六维度投票，多数方胜出                  │
└─────────────────────────────────────────┘
```

#### 2.5.4 裁决结果写入

裁决完成后，在新 segment 中写入冲突记录：

```markdown
### 10. 记忆冲突裁决（如有）

| # | 冲突维度 | 旧记忆 (S#N) | 新信息 | 裁决 | 理由 |
|---|---------|-------------|--------|------|------|
| 1 | 决策 | 用 Electron | 改用 Tauri | 🟡 演化 | 竞品调研后发现 opcode=Tauri，同栈复用 |
| 2 | 事实 | PRECISE-7 有效 | PRECISE-7 无源 | 🔴 纠正 | 2轮搜索无结果，旧记忆为幻觉 |
```

同时在 `memorydistillation.md` 的压缩段中追加一行：
```
**冲突**：[冲突摘要，🟡/🔴 标记]
```

#### 2.5.5 旧记忆不删除

**[HARD] 旧 segment 永远不修改、不删除。** 冲突裁决只在新 segment 中记录。这保证了：
- 记忆时间线完整（可以回溯「当时为什么这么想」）
- 符合知识进化协议（状态标注，不删文件）
- 防止记忆翻转（A→B→A 循环时有完整记录可查）

#### 3B: 更新 4-file system（按功能路由）

9 维度信息按功能路由到 4 个文件：

```
维度 → 目标文件 → 操作模式
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

维度 7 (TODO/未完成)     → working.md           → OVERWRITE（最新状态）
维度 3 (新 VERIFIED 事实) → facts.md            → APPEND 新发现
维度 4 (踩坑) + 维度 2 (新策略) → strategies.md → APPEND 新策略/反模式
全部维度 (时间线记录)     → episodes.md          → APPEND 新 segment

路由规则：
- working.md 总是被覆写（最新 TODO + 当前任务 + 上次 /install 时间）
- facts.md 仅当有新 VERIFIED 事实时追加（环境变化/新工具/新权限）
- strategies.md 仅当有新策略或反模式时追加
- episodes.md 每次 /memory 都追加新条目（一行摘要 + tags）
- 每个 .md 更新后，必须从它重新生成对应的 .distilled.md
```

**WHY:** 4-file system 是 /install bootstrap 的读取源。不更新 = 下一个 session 加载过期信息 = 跨 session 不一致。

#### 3B 验证:
```
□ working.md 已更新（当前任务 + TODO + timestamp）
□ episodes.md 已追加新条目
□ facts.md 已追加（如有新事实）或跳过（无新事实）
□ strategies.md 已追加（如有新策略）或跳过（无新策略）
□ 所有更新的 .md 都已重新生成 .distilled.md
```

### 第四步：写入 memorydistillation.md（压缩版）

对第三步生成的 segment 内容，执行**五层蒸馏**后追加到 `~/Desktop/memorydistillation.md` 末尾：

**五层蒸馏流水线（同 /最小无损蒸馏）：**
1. **L1 清除装饰** — 删分隔线、空行、装饰 emoji、自明标题
2. **L2 电报体** — 删虚词连接词，符号替代（→ ≠ ∵ ∴ + >）
3. **L3 结构压缩** — 表格→单行、列表→逗号分隔、合并同类项
4. **L4 语义去重** — 同一事实只保留最精确的表述
5. **L5 可推导裁剪** — 能从其他信息推导出的内容删除

**压缩后格式：**

```markdown
---

## S#[N] [YYYY-MM-DD HH:MM] #标签1 #标签2

**意图**：[一句话]
**决策**：[关键决策，逗号分隔]

**坑**：[踩坑+解法，逗号分隔]
**文件**：[路径列表]
**TODO**：[未完成项]
**用户**：「原话摘录」
```

**目标压缩率：≤ 原 segment 的 25%**

## 特殊场景处理

### 场景 A：首次调用（文件不存在）

1. 创建 `~/Desktop/memory.md`，首行写文件头
2. 创建 `~/Desktop/memorydistillation.md`，首行写文件头
3. Segment 编号从 #1 开始
4. 捕获范围 = session 开始 → 当前

### 场景 B：对话刚开始就调用

如果从 session 开始到调用 `/memory` 之间几乎没有内容（< 3 轮对话），输出：

```
⚠️ 当前对话内容太少，没有值得记忆的信息。
   建议：先进行一些工作，再调用 /memory 保存。
```

### 场景 C：文件过大

当 `memory.md` 超过 50,000 字符时，在确认输出中追加提醒：

```
⚠️ memory.md 已超过 50K 字符。建议：
  1. 将旧 segment 归档到 ~/Desktop/memory-archive-YYYY-MM.md
  2. 或删除已不需要的早期 segment
```

### 场景 D：连续多次调用

如果上一个 `/memory` 和当前之间没有新内容，输出：

```
ℹ️ 上次 /memory 之后没有新的对话内容，无需重复保存。
```

## 铁律

1. **[HARD] 全量提取** — 9 维度全覆盖，不遗漏任何维度。宁多勿漏。
2. **[HARD] 追加不覆盖** — 永远是 APPEND 模式，永远不覆盖已有内容
3. **[HARD] 双文件同步** — memory.md 和 memorydistillation.md 必须同时写入，缺一不可
4. **[HARD] Segment 编号连续** — 编号必须从文件中已有的最大编号 +1，不跳号
5. **[HARD] 用户原话必引** — 维度 9 中用户的关键原话必须用「」引用，这是最重要的记忆锚点
6. **[HARD] 写入前必须冲突扫描** — 第 2.5 步不可跳过。新信息与旧记忆冲突时必须裁决，不裁决就写入 = 记忆污染
7. **[HARD] 旧 segment 不修改** — 冲突裁决只写在新 segment 的维度 10 中，旧 segment 永远保持原样
8. **[HARD] 🔴冲突必须深度裁决** — 发现红色冲突时，必须走三层裁决（事实核验→纵深追问→六维度交叉），禁止简单覆盖
9. **[SOFT] 蒸馏率 ≤ 25%** — 压缩版目标不超过全保真版的 25%
10. **[PREF] 标签可搜索** — 主题标签使用 #英文 或 #中文，便于 Grep 检索
